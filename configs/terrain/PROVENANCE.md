# PROVENANCE.md — configs/terrain/ebc_route.json

Small, pinned, offline route artifact for the geographic-risk guard's `MissionContext`
(mandatory deliverable 14 in `docs/plan.md`). Generated by
`scripts/prepare_terrain_artifact.py`; **not** fetched at runtime — the guard only reads
the committed JSON file.

## What it is

Eight named waypoints along the standard Everest Base Camp (EBC) trek, Khumbu region,
Nepal, each with coordinates (WGS84 / EPSG:4326) and published elevation. This is a
waypoint/route sample, not a gridded DEM raster — appropriate for a bounded demo route,
not general terrain queries. Distances between consecutive waypoints are great-circle
(haversine), not actual trail distance (shorter than the real switchbacked trail).

Wikipedia coordinates for these articles are themselves sourced from a mix of survey
data, OpenStreetMap, and GeoNames per Wikipedia's own citation practice — treat this
artifact as approximate/representative, not survey-grade. Elevations in some source
articles vary slightly between infobox/text/climate-table (a few meters); the value used
here is the primary infobox figure.

## Derived fields (computed, not sourced)

`slope_deg_from_prev`, `cumulative_distance_m`, `distance_from_prev_m`,
`distance_to_safe_waypoint_m`, `exposure_class` are all computed by
`scripts/prepare_terrain_artifact.py` from the raw coordinates/elevations above — see
that script's docstrings for the exact formulas and the `exposure_class` heuristic
(explicitly a bounded proxy, not a validated avalanche/exposure model).

`safe_waypoint_names` (`Lukla`, `Phakding`, `Namche Bazaar`) is a judgment call, not a
sourced fact: these are the lower-altitude, better-served stops on the route (Lukla has
the airport). Documented here so it can be challenged/changed without spelunking code.

## Regenerating

`uv run python scripts/prepare_terrain_artifact.py` — only re-run (with network access)
if the route or waypoint list needs to change; the script is deterministic given its
hardcoded `WAYPOINTS` table, so re-running with no code changes reproduces the same
output. Commit the resulting `ebc_route.json` — the runtime never fetches this live.
